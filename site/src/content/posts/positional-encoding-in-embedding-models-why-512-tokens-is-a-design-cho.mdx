Your best evidence may never reach the encoder. A pipeline can accept 2,000 tokens, return a clean embedding, and still drop the tail where the answer lives. In production, that fails quietly: the vector looks plausible, nearest neighbors look plausible, and the wrong chunk wins. Choose an embedding model’s usable context length by retrieval measurements, not its advertised token limit. Start by verifying what reaches the model, then separate truncation, order sensitivity, and padding effects.

## 512 tokens is a design choice, not a semantic boundary

Position is not text. It enters before pooling, either as an input embedding signal or inside attention itself, and that choice shapes what the final vector represents.

Encoder models often use learned absolute position embeddings added at the input. Classic BERT-style checkpoints use a fixed table, which makes its bounds an architectural constraint. Sinusoidal encodings are also added at the input, but the positions are computed, not learned, as described in [Attention Is All You Need](https://arxiv.org/abs/1706.03762). RoPE rotates queries and keys inside attention layers; attention-bias schemes modify attention logits.

Pooling happens after token states have already become position-dependent. Mean pooling does not erase position: it averages hidden states changed by position, attention, and content interactions.

One subtle point matters: averaging token-plus-position embeddings at fixed length is permutation-invariant **before contextualization**. Reordering tokens preserves their sum and the sum of the positional vectors. Order sensitivity emerges through contextualization; a sinusoidal-average demonstration cannot predict final embedding drift.

## Four families, five distinct engineering choices

T5-style relative bias and ALiBi belong to the same attention-bias family, but they impose different distance behavior. [ALiBi’s primary paper](https://arxiv.org/abs/2108.12409) describes its head-specific linear attention penalties.

| Family / insertion point | Architectural and training boundary | Pooling / chunking consequence | Choose when |
|---|---|---|---|
| Learned absolute / added at input | Finite position table; resizing needs adaptation, not assumed extrapolation | Chunk below the deployed cap; retain trained pooling | Bounded passages deliver strong corpus recall |
| Sinusoidal / added at input | Positions are computable; generalization beyond training lengths is unproven | Evaluate longer inputs; pooling provides no automatic immunity | The checkpoint already uses it and passes retrieval evaluations |
| T5 relative bias / attention logits | Distances map to buckets; sufficiently large distances share the terminal bucket | Test whether remote evidence remains distinguishable and retrievable | Evaluated long-input behavior fits the task |
| ALiBi / attention logits | Head-specific linear distance penalties; no absolute table to extend | Remote evidence can receive increasingly negative attention bias | Long-input retrieval demonstrates that the distance bias is acceptable |
| RoPE / per-layer Q/K rotation | Runtime and training limits remain; extension settings change geometry | Preserve trained pooling and evaluate layout, tail recall, and scaling | A native or adapted long-context checkpoint earns its cost |

For a learned table with 512 entries, valid position IDs are **0 through 511**. A tokenizer or wrapper can truncate before forward execution, preventing an invalid lookup. An actual out-of-range lookup normally fails unless the architecture or position handling has been modified; it does not simply produce a lower-quality embedding.

Sinusoidal encodings avoid that learned-table boundary, but computable positions do not establish trained-length generalization.

RoPE’s relative-distance mechanism is precise. For query and key vectors at positions `m` and `n`:

```text
(R_m q)ᵀ(R_n k) = qᵀ R_(n−m) k
```

A uniform shift preserves that pairwise geometry under standard RoPE. Adding a prefix is **not** such a shift: it introduces attended content, new content-to-prefix distances, and potentially different special-token placement. Padding tests, prefix changes, and text reordering must therefore be separate experiments.

## Read the deployed pipeline, not just `config.json`

For absolute-position encoders, inspect `max_position_embeddings`, `position_embedding_type`, and the actual position table. For RoPE models, inspect `rope_scaling`, `rope_theta`, and architecture-specific position handling. Then inspect tokenizer settings, wrapper limits, and pooling modules.

The minimum-limit heuristic applies to straightforward absolute-position pipelines with compatible position numbering. It is not a universal formula for RoPE, relative bias, or architectures with position offsets. A tokenizer’s enormous `model_max_length` can be a sentinel meaning “no known limit,” not permission to submit that many tokens.

Distinguish these boundaries:

- **Architecture:** Which position IDs can the implementation execute?
- **Wrapper:** Does preprocessing truncate before execution?
- **Training:** Which lengths and input layouts did embedding training use?
- **Retrieval:** At which lengths does evidence remain retrievable?

The [Transformers padding and truncation documentation](https://huggingface.co/docs/transformers/main/en/pad_truncation) describes tokenizer-side behavior. Sentence Transformers exposes its wrapper limit through [`max_seq_length`](https://www.sbert.net/docs/package_reference/sentence_transformer/SentenceTransformer.html#sentence_transformers.SentenceTransformer.max_seq_length). Neither establishes long-document quality.

Preserve the checkpoint’s documented role-specific query and document templates, and freeze each independently. They may intentionally differ. Prefix tokens consume budget and participate in attention; removing or “standardizing” them changes the input contract.

A checkpoint-specific inspection should record the resolved model revision, primary configuration, model-card input convention, tokenizer settings, and Sentence Transformers module metadata where present.

### Resolve E5 and GTE from their saved artifacts

For **E5-base-v2**, inspect the checkpoint’s `config.json`, model card, module sequence, and saved Pooling configuration together. For **GTE-Qwen2-1.5B-instruct**, inspect the same primary configuration and card, including the card’s pooling implementation and query/document construction. Do not transfer a BERT position limit, mean-pooling assumption, or prefix convention to a decoder-derived checkpoint.

The following inspection prints the actual configured limits and positional fields from a resolved snapshot, alongside the card’s pooling and input instructions. It does not substitute plausible checkpoint values for artifact inspection.

```python
import json
from pathlib import Path
from huggingface_hub import snapshot_download

for model_id in ("intfloat/e5-base-v2", "Alibaba-NLP/gte-Qwen2-1.5B-instruct"):
    root = Path(snapshot_download(model_id, allow_patterns=["*.json", "README.md"]))
    config = json.loads((root / "config.json").read_text())
    print(model_id, "revision:", root.name)
    print({k: config.get(k) for k in (
        "model_type", "position_embedding_type", "max_position_embeddings",
        "rope_theta", "rope_scaling")})
    for filename in ("modules.json", "sentence_bert_config.json", "1_Pooling/config.json"):
        artifact = root / filename
        if artifact.exists():
            print(filename, artifact.read_text())
    print("model card:\n", (root / "README.md").read_text())
```

Record the positional scheme from the architecture and configuration, the configured limit from the downloaded artifact, and pooling and role requirements from the card and module metadata. A missing positional field is not evidence that the model has no position encoding.

## Measure truncation, order, and padding separately

The reference must use the same model and pooling pipeline. First establish the largest supported **total-token** budget, including the role prefix and special tokens. Immediately before forward execution, verify the reference’s final sequence length and mask.

If the document fits, compare against its full-document embedding. Otherwise report **maximum-supported-prefix similarity**, plus reference coverage. A curve against an already-clipped reference says nothing about fidelity to the missing tail.

The following example deliberately supports a narrow pipeline: a conventional BERT absolute-position Sentence Transformer with prefix-only role templates **and trained, mean-only pooling**. Its saved Pooling module must enable mean pooling and no other pooling mode. CLS, last-token, max, weighted mean, and mixed modes are rejected.

That restriction matters for the padding experiment. A CLS implementation selecting the first array position can select padding under left padding, overwhelming the positional effect the probe is intended to isolate.

The direct forward path does **not** automatically reproduce `encode()`-time prompt processing. This probe therefore rejects pooling that excludes prompt tokens and checkpoints with configured encode-time prompts. Prefixes are included explicitly in tokenization, attention, and mean pooling.

Install the dependencies without speculative version pins:

```bash
pip install torch transformers sentence-transformers huggingface-hub
```

The runnable default is `intfloat/e5-base-v2`, with `passage: ` for documents and `query: ` for queries. The downloaded pipeline must pass the checks before producing a vector. Environment overrides retain the same narrow contract; changing a prefix requires checking the selected checkpoint’s documented input convention. Supply `MODEL_REVISION` to reproduce an existing deployment and `DOCUMENT_PATH` for the document to inspect.

```python
import os
from pathlib import Path
import torch
import torch.nn.functional as F
from huggingface_hub import snapshot_download
from sentence_transformers import SentenceTransformer, models

path = snapshot_download(os.getenv("MODEL_ID", "intfloat/e5-base-v2"),
                         revision=os.getenv("MODEL_REVISION", "main"))
print("revision:", Path(path).name)
model = SentenceTransformer(path).eval()
modules = list(model.children())
assert isinstance(modules[0], models.Transformer)
assert isinstance(modules[1], models.Pooling)
assert all(isinstance(m, models.Normalize) for m in modules[2:])
trans, pool = modules[:2]
pc = pool.get_config_dict()
modes = {k: v for k, v in pc.items() if k.startswith("pooling_mode_")}
assert modes.get("pooling_mode_mean_tokens") is True
assert all(not v for k, v in modes.items() if k != "pooling_mode_mean_tokens")
assert pc.get("include_prompt") is True, "Prompt-excluding pooling is unsupported"
assert not model.prompts and model.default_prompt_name is None
tok, hf = trans.tokenizer, trans.auto_model
assert hf.config.model_type == "bert"
assert hf.config.position_embedding_type == "absolute" and tok.pad_token_id is not None
table = hf.embeddings.position_embeddings.num_embeddings
limits = [model.max_seq_length, trans.max_seq_length,
          hf.config.max_position_embeddings, table]
if 0 < tok.model_max_length < 10**20:
    limits.append(tok.model_max_length)
cap, special = min(limits), tok.num_special_tokens_to_add(pair=False)
doc_prefix = os.getenv("DOC_PREFIX", "passage: ")
query_prefix = os.getenv("QUERY_PREFIX", "query: ")
print("cap:", cap, "pooling:", pc)

def build(text, prefix, budget):
    assert special < budget <= cap
    p = tok(prefix, add_special_tokens=False)["input_ids"]
    raw = tok(prefix + text, add_special_tokens=False)["input_ids"]
    assert raw[:len(p)] == p and len(p) < budget - special
    kept = raw[:budget - special]
    row = tok.prepare_for_model(kept, add_special_tokens=True, truncation=False,
                               return_attention_mask=True, return_special_tokens_mask=True)
    flags = row.pop("special_tokens_mask")
    assert [i for i, s in zip(row["input_ids"], flags) if not s] == kept
    assert len(row["input_ids"]) == len(kept) + special <= budget
    assert all(row["attention_mask"])
    return row, len(kept) - len(p), len(raw) - len(p)

@torch.inference_mode()
def forward(rows):
    batch = tok.pad(rows, padding=True, return_tensors="pt")
    width = batch["input_ids"].shape[1]
    assert width <= cap and width <= table
    positions = hf.embeddings.position_ids[:, :width].expand(len(rows), -1)
    for j, row in enumerate(rows):
        mask = batch["attention_mask"][j].bool()
        assert batch["input_ids"][j, mask].tolist() == row["input_ids"]
        assert int(mask.sum()) == len(row["input_ids"])
        assert torch.all(batch["input_ids"][j, ~mask] == tok.pad_token_id)
        pos = positions[j, mask]
        assert int(pos.min()) >= 0 and int(pos.max()) < table
        print("consumed:", int(mask.sum()), "positions:", (int(pos[0]), int(pos[-1])))
    return F.normalize(model({k: v.to(model.device) for k, v in batch.items()})
                       ["sentence_embedding"], dim=-1)

document = Path(os.environ["DOCUMENT_PATH"]).read_text()
ref, kept, total = build(document, doc_prefix, cap)
label = "full-document similarity" if kept == total else "maximum-supported-prefix similarity"
print(label, "reference coverage:", kept / max(total, 1))
ref_vec = forward([ref])[0]
for budget in (128, 256, 512, 1024):
    if budget <= cap:
        print("budget:", budget, label,
              float(forward([build(document, doc_prefix, budget)[0]])[0] @ ref_vec))
a = "The contract expires on Friday, and renewals require legal approval."
controls = ("Renewals require legal approval, and the contract expires on Friday.",
            "The contract expires on Monday, and renewals require legal approval.")
target = build(a, query_prefix, cap)[0]
baseline = forward([target])[0]
for name, text in zip(("reorder", "changed expiry"), controls):
    print(name, float(forward([build(text, query_prefix, cap)[0]])[0] @ baseline))
longer = build(a * 20, query_prefix, cap)[0]
assert len(longer["input_ids"]) > len(target["input_ids"])
original_side = tok.padding_side
try:
    tok.padding_side = "left"
    left = forward([target, longer])[0]
    tok.padding_side = "right"
    print("padding cosine:", float(left @ forward([target, longer])[0]))
finally:
    tok.padding_side = original_side
```

The probe constructs token IDs directly; it never decodes truncated IDs back into text. Joint prefix-and-content tokenization follows the supported input convention, while the prefix check rejects a boundary mismatch. Special-token space is reserved before slicing, and final mask and position checks execute immediately before forward execution.

**Model-consumed length** counts attended tokens in each final input. Reference coverage counts retained document tokens only, excluding prefix and special tokens. Additional serving-layer preprocessing or limits must also be reproduced before treating this as a deployment-equivalent probe.

### Interpret drift against controls and retrieval labels

A large change under a meaning-preserving reorder can indicate unwanted order sensitivity. Compare it with the nearby meaning-changing control and with retrieval labels; semantic equivalence does not require identical vectors.

The padding probe genuinely pads the short target by batching it with a longer input. It preserves identical real-token sequences, restores tokenizer state, and uses evaluation plus inference mode. It prints the BERT position IDs selected for real tokens: left padding shifts those absolute positions, so a difference is not automatically a bug.

For a RoPE pipeline, inspect its actual position-ID construction and causal last-token selection instead. Correct masking, pooling, and consistent position handling should preserve standard RoPE’s pairwise geometry under a uniform shift. Wrong terminal-token selection or pooling padded states can dominate the result.

Cosine stability is not retrieval stability. Small vector movements can reorder tightly packed neighbors. Pair these diagnostics with recall@k or nDCG, sliced by evidence position.

## RoPE extension changes the embedding contract

Context-extension methods alter different parts of the geometry:

- **Position interpolation** compresses position indices into a shorter effective range.
- **Frequency adjustment**, including NTK-aware approaches, changes the rotary frequencies and therefore how dimensions represent distance.
- **YaRN** combines frequency-dependent interpolation/extrapolation with attention scaling rather than applying one uniform position compression.

See the primary papers for [RoPE](https://arxiv.org/abs/2104.09864), [position interpolation](https://arxiv.org/abs/2306.15595), and [YaRN](https://arxiv.org/abs/2309.00071).

These methods do not establish a universal short-context-versus-long-context trade-off for embeddings. Retrieval gains and short-context regressions require embedding-specific evaluation. Generation perplexity is not evidence that nearest neighbors improved.

Changing RoPE settings also invalidates affected cached states. Key rotations change directly; deeper contextual hidden states, including the values projected from them, can change too. Recompute affected caches rather than rotating stored keys and assuming the remainder is reusable. The [Transformers KV-cache documentation](https://huggingface.co/docs/transformers/main/en/cache_explanation) explains what those caches retain.

Embedding pipelines usually do not reuse KV caches across documents, but persisted document vectors still belong to the old contract. A geometry change requires re-encoding or an evaluated migration—not mixing vectors merely because their dimensions match.

## Choose chunks by evidence recall and attention cost

**ESTIMATE, assuming a 512-token total budget, 16 prefix tokens, and two special tokens:** the content budget is `512 − 16 − 2 = 494`. A 2,000-token body retains `494 / 2000 = 24.7%` in one input.

With 64-token overlap, the stride is `494 − 64 = 430`. A 10,000-token body needs:

```text
1 + ceil((10000 - 494) / 430) = 24 chunks
```

Increasing dense-attention length from 512 to 2048 creates `(2048 / 512)² = 16` times as many attention-score elements per head and layer. That does **not** imply 16 times end-to-end latency or memory: optimized kernels need not materialize the full score matrix, and other operations contribute to cost.

Chunking increases vector count, overlap duplication, and retrieval orchestration. Long inputs increase attention work and ask one pooled vector to represent more evidence. Choose between them with retrieval quality, ingestion throughput, query latency, and index size—not the advertised limit alone.

Retain the pooling used during embedding training unless an evaluated adaptation supports changing it:

- **Mean pooling:** localized evidence can be diluted as unrelated token states enter the average. Contextualization makes the effect more complex than a simple token-count ratio.
- **CLS pooling:** useful sentence-level behavior depends on training that makes CLS a suitable summary.
- **Causal last-token pooling:** select the last attended real token according to the checkpoint’s convention, not the last padded array element.

L2 normalization rescales vectors; it does not subtract shared components. Centering and whitening change the geometry and require separate retrieval evaluation.

## Diagnose failures before changing position settings

| Symptom | Likely cause | Mitigation |
|---|---|---|
| Tail facts disappear | First-N truncation | Chunk documents; evaluate tail-evidence queries |
| A “full-document” curve is almost flat | Reference was silently clipped | Verify final reference length; report coverage and maximum-supported-prefix similarity |
| Identical real tokens drift under padding | Masking, position handling, or pooling mismatch; absolute positions may also shift legitimately | Inspect actual position IDs, masks, and real-token selection through the same pooling pipeline |
| Unrelated long documents become similar | Shared boilerplate or representation anisotropy | Remove boilerplate; evaluate centering separately; attribute effects to position only after a controlled experiment |
| Retrieval gradually degrades after deployment | Ingestion workers mix embedding contracts | Fingerprint contracts; use versioned indexes and atomic cutovers |

The last failure is easy to miss at scale: workers can produce the same vector dimension while disagreeing on revision, templates, pooling, normalization, or RoPE settings.

## What most teams get wrong

- **They treat tokenizer limits as authoritative.** Inspect architecture, tokenizer sentinels, wrapper limits, and serving preprocessing together.
- **They force identical query and document prefixes.** Preserve documented role-specific templates and freeze each independently.
- **They switch pooling based on architecture folklore.** Retain trained pooling until retrieval evaluation justifies an adaptation.
- **They choose chunk size from cosine alone.** Use labeled retrieval metrics with evidence-position slices.
- **They change context settings during incremental ingestion.** Treat geometry changes as index-version boundaries.

## Freeze the contract before scaling ingestion

Create a contract fingerprint containing the resolved model revision, tokenizer revision and settings, query/document templates, pooling, normalization, and RoPE settings. Attach it to ingestion jobs and index metadata. Build changed contracts in versioned indexes and switch query routing atomically.

Before committing to a usable context length:

1. Establish the largest supported total-token input in the actual deployed pipeline.
2. Verify reference length immediately before forward execution; report document coverage.
3. Run truncation, meaning-preserving reorder, meaning-changing control, and genuinely padded probes.
4. Compare chunk sizes using recall@k or nDCG, especially for tail evidence.
5. Freeze role-specific templates and the complete embedding contract.
6. Rebuild or migrate affected indexes when that contract changes.

512 tokens is a design choice, not a semantic boundary. The usable length that matters is the one your retrieval measurements can defend.
